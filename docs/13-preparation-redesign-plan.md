# Preparation: план доработки перед хакатоном

## Цель и договорённости

Сделать Preparation удобным рабочим пространством подготовки к сопернику: большой чат слева, три блока настройки справа, переход на доску с согласованным планом и конкретными ходами.

Приоритет пользователя — читаемый, красивый интерфейс в стиле остальных страниц и работающий основной сценарий в условиях близкого дедлайна. Сначала согласован план; реализация этого плана пока не начата. Текущая задача — сохранить контекст и план, без изменения кода.

## Что уже реализовано

- Поиск игрока по кнопке, выбор по FIDE ID и переход в профиль.
- Поля игрока, цвета, дебюта и заметок.
- Создание обзора через действие `repertoire`, сохранение ответа в разговоре `prep:<study id>`.
- Сохранение черновиков подготовки и передача полей подготовки на доску.
- Страница использует общие цвета проекта, но текст мелкий, чат расположен слишком низко.

В GitHub проверены все шесть веток и оба PR. Отдельная готовая реализация Preparation от напарника не найдена. Текущая работа — развитие местной реализации. В checkout много других незакоммиченных изменений: сохранять их, не заменять файлы целиком без сверки.

## Подтверждённые проблемы

### 1. Каталог находит партии, тренер получает ноль

`library/coach/context.py` выбирает только игры со статусом `accepted`.

Для Magnus Carlsen, FIDE ID `1503014`, в локальной базе:

| Статус | Количество |
| --- | ---: |
| quarantine | 716 |
| rejected | 135 |
| accepted | 0 |
| Всего | 851 |

Причины ограничений пересекаются: `unverified_official_event` — 851; отсутствие исторического рейтинга белых/чёрных — по 783; `invalid_pgn` — 135; `unknown_game_date` — 13. Это не взаимоисключающие группы.

Неподтверждённый официальный статус турнира не равен невозможности анализировать корректные ходы. При этом нельзя автоматически считать все записи пригодными или переименовывать их в подтверждённые OTB-партии.

### 2. Ответ чата не помогает продолжить подготовку

`library/coach/blueprints/repertoire.md` при пустой выборке предлагает выбрать другого игрока с FIDE ID, даже когда текущий игрок уже правильно идентифицирован. В предоставленном пользователем разговоре запросы доходят до модели и ответы сохраняются; проблема подтверждена в контексте и поведении ответа, а не как полный отказ API.

В примере пользователя поле цвета — White, но в заметках указана игра чёрными. Тренер должен уточнить противоречие и не формировать окончательный план до его разрешения.

### 3. Доска и чат не продолжают подготовку полностью

Preparation сохраняет выбранные поля и открывает `/analysis`. Конкретная партия, линия и итоговый план не передаются. `boardConversation()` в `frontend/src/App.tsx` принимает идентификаторы `analysis`, `import`, `demo`, но не `prep`, поэтому создаётся отдельный разговор. Предыдущая проверка подтвердила наличие соперника в контексте доски, но не общую историю чата.

### 4. Интерфейс и поиск

Основные поля и подписи слишком мелкие. Чат находится под длинной формой. Поиск запускается только отправкой формы. Нет удобного непрерывного сценария обсуждения и подтверждения плана.

## Целевой экран

```text
Preparation    [выбор сохранённой подготовки]    [+ Новая]
┌─────────────────────────────────┬────────────────────────┐
│                                 │ 1. Соперник            │
│ Большой чат с тренером           │ Живой поиск            │
│                                 │ Карточка → профиль     │
│ Обзор партий и источники        ├────────────────────────┤
│ Обсуждение цели и вариантов      │ 2. План на партию      │
│ Уточняющие вопросы               │ Игрок, цвет, дебют     │
│                                 │ Цель и заметки         │
│ Карточка итогового плана         ├────────────────────────┤
│ [Перейти к анализу на доске]     │ 3. Разбор и готовность │
│                                 │ Выборка и источники    │
│ [Сообщение тренеру…] [Отправить]  │ [Сформировать план]    │
└─────────────────────────────────┴────────────────────────┘
```

- Примерно 65% ширины — чат, 35% — панель подготовки.
- Сообщения около 18 px; поля и кнопки около 16 px; вторичные подписи остаются читаемыми.
- Общая палитра, шрифты и элементы управления проекта; компактная шапка вместо большого рекламного заголовка.
- Чат и правая панель имеют понятную прокрутку; ввод сообщения доступен постоянно.
- На узком экране — чат с раскрываемой панелью подготовки, без горизонтального переполнения.

## План реализации

### Шаг 1. Исправить выборку для подготовки

1. Проверить причины ограничений и доступность исходного PGN для выбранного игрока.
2. Определить отдельную политику пригодности для анализа: корректные ходы и подтверждаемая связь с выбранным игроком; официальный статус турнира показывать отдельно.
3. Разрешить подходящие записи `quarantine` с явным указанием ограничений. Не снимать фильтр статуса вслепую, не менять классификацию исходной базы.
4. Исключать некорректные PGN и сомнительное сопоставление личности.
5. Вернуть в контекст и UI числа «найдено / использовано / исключено», период, цвет, причины исключения и ссылки на примеры.
6. При нуле пригодных партий объяснять конкретную причину; разрешать тренеру обсуждать общую подготовку без выдуманных привычек соперника.

### Шаг 2. Исправить работу чата и состояния подготовки

1. Сохранить один идентификатор `prep:<study id>` для подготовки, списка чатов и доски.
2. Передавать в каждый запрос актуальные поля, выборку и сохранённый итоговый план.
3. Заменить подсказки о текущей позиции на вопросы подготовки, когда доски ещё нет.
4. Уточнять противоречия: цвет в форме и заметках, неподтверждённый соперник, невыбранная линия.
5. Отделить обзор репертуара от согласованного плана. Итоговый план содержит цель, цвет, дебют, рекомендации, аргументы, источники и выбранную линию.
6. Сохранять план структурированно, а не только текстом внутри ответа модели.
7. Защитить интерфейс от запоздалых ответов при переключении подготовок; показывать ошибки и повтор запроса без дублирования сообщений.

### Шаг 3. Перестроить UI и добавить живой поиск

1. Перенести чат в большую левую колонку, три шага — в правую.
2. Увеличить текст, поля, кнопки и интервалы; перенести историю подготовок в верхний переключатель.
3. Запускать поиск при изменении строки с задержкой примерно 250 мс.
4. Отменять предыдущие запросы и не применять устаревшие ответы; очищать результаты при пустой строке.
5. Показывать имя, FIDE ID, количество партий и ссылку на профиль. Не смешивать игроков только по сходству имён.
6. Развести состояния загрузки, ошибки, отсутствия совпадений и выбранного игрока.
7. После смены соперника явно помечать старый обзор как относящийся к прежнему игроку либо скрывать его из текущего плана, сохраняя историю.

### Шаг 4. Передавать подготовленную позицию на доску

1. В плане дать выбрать исходную партию или конкретную линию для изучения.
2. Проверить легальность последовательности ходов, сохранить дерево, начальную позицию, активный узел и происхождение линии.
3. Кнопка «Перейти к анализу» передаёт дерево, выбранный узел, цвет, соперника, итоговый план, ссылки на источники и идентификатор текущего чата.
4. Доска открывается на выбранной позиции с нужной ориентацией и той же историей разговора.
5. Если конкретная линия ещё не выбрана, предложить выбрать её. Не обещать готовый анализ при переходе к пустой начальной позиции.
6. Сохранить результат так, чтобы повторное открытие подготовки и перезагрузка восстанавливали план и анализ.

## Порядок и ограничения перед дедлайном

1. Выборка партий и корректное объяснение отсутствующих данных.
2. Общий чат и сохранение структурированного плана.
3. Крупный интерфейс и живой поиск.
4. Передача одной выбранной партии/линии на доску.
5. Проверка полного сценария и устранение обнаруженных ошибок.

Для первой рабочей версии достаточно одной выбранной линии и одного плана на подготовку. Массовые отчёты, сложное управление проектами и расширенный репертуар отложить. Не выдавать сырые данные каталога за подтверждённую историю OTB-партий.

## Проверка готовности

Основной сценарий:

1. Ввести `Carlsen` постепенно: результаты обновляются без нажатия Search и без устаревших ответов.
2. Выбрать Magnus Carlsen, FIDE `1503014`; открыть правильный профиль.
3. Увидеть реальные размеры каталога и пригодной выборки с объяснением различий.
4. Задать цвет и цель; при противоречии получить уточняющий вопрос.
5. Получить обзор с источниками и обсудить его обычными сообщениями.
6. Сформировать итоговый план, выбрать партию/линию и перейти на доску.
7. Увидеть подготовленные ходы, выбранную позицию, соперника, план и тот же чат.
8. Вернуться к подготовке и перезагрузить: контекст и результаты сохраняются.

Дополнительно проверить: пустой поиск, игрок без партий, отсутствие FIDE ID, ошибка AI, переключение подготовки во время запроса, широкий и узкий экран. Выполнить сборку и целевые проверки выборки/передачи состояния; не тратить время на несвязанные изменения.
